# Three-band crossover and compression

The standalone HyperDSP Multiband filter and native:hyperdsp_multiband_filter:1 graph node share Multiband and ThreeBandCrossover. The crossover uses existing TPT state-variable Butterworth sections: cascade two at each low/high edge to form a fourth-order Linkwitz–Riley pair, then phase-align the low branch with the upper crossover's second-order all-pass. The unmodified sum has unity magnitude and frequency-dependent phase. The internal wet/dry mix uses the recombined uncompressed bands, not the original unfiltered signal. There is no fixed sample-buffer delay; a separate graph branch cannot be phase-aligned just by integer latency compensation.

Low crossover 60–500 Hz (default 250); high crossover 1000–8000 Hz (default 2500), clamped to 45% of sample rate. State is independent per channel. Three instances of the existing linked peak Dynamics compressor process each band independently; each band has threshold, ratio and makeup, with shared attack/release/knee. The engine uses bounded preallocated 256-frame chunks, 1–8 channels and 8–192 kHz. Continuous settings use existing Dynamics and mix ramps. Crossovers are base-only graph parameters (no macro binding) and changing them in standalone OBS settings resets state. Standalone bypass returns unmodified audio. No dedicated standalone modulation routes, band solo, band meters, lookahead, true-peak limiting, or external sidechains yet; graph-level modulation is available through exposed controls.

Verification: core neutral recombination across five sample rates (8, 44.1, 48, 96, 192 kHz) and frequencies from 80 to 3500 Hz, including both crossover frequencies; magnitude deviation within 0.12 dB and stereo proportionality within 1e-5. Low-only compression at 80 Hz yields amplitude ratio 0.100013 while 6 kHz remains 1.0. Graph validation accepts ratio mapping but rejects crossover mapping. Actual libobs downstream capture measures low RMS 0.0353599, high RMS 0.353553, bypass RMS 0.353553 and identical graph compression; changing the generated OBS macro to 0 restores RMS 0.353515. Registry/property metadata parity, CLI bindability and all-mode partition tests cover the new family. No physical listening or worst-case callback CPU profiling yet.

The crossover and phase-matched chunk processor now reside in the shared three_band.hpp bank, also consumed by three-band transient shaping. The compressor settings and signal path are unchanged.

Graph Monitor Node activity now displays independent held detector peaks and smoothed gain reduction for all three compressor bands; these are not output RMS meters. Standalone properties now offer Open live analysis with the same detector and reduction meters.

The standalone Open live analysis window also provides draggable crossover boundaries (preview while dragging, apply on release) and per-band threshold, ratio and makeup controls. See [standalone analysis](filter-analysis.md).

The standalone OBS adapter publishes fixed-size settings snapshots on the control path and adopts them at audio block boundaries. Ordinary parameter updates preserve the existing detector, filter and ramp histories, without a processing mutex or contention-induced dry fallback. Explicit bypass/mode/crossover changes retain their documented reset behavior. Telemetry is invalidated on accepted updates and is published only for the currently adopted generation; telemetry snapshot contention can skip a display update, not audio processing.

The [Linux callback audit](realtime-profiling.md) includes multiband compressor with concurrent settings edits and allocation instrumentation. The [native CI matrix](ci.md) runs the required numerical and OBS integration tests on all eight targets; neither establishes exhaustive mode coverage or a physical-device deadline guarantee.
