# Effect Builder

Effect Builder is an optional native Qt dock for authoring deterministic audio effects, analogous to HyperShader's Shader Builder. The intended experience and proposed implementation order below preserve the broader design direction.

## Intended experience

A dock for composing, previewing, saving and applying reusable deterministic audio effects, not just browsing plugins or changing one filter's parameters. A compact theme-aware, dockable interface with an editable signal graph, searchable blocks, a parameter inspector and a visible modulation layer. Expose selected graph parameters as controls on the resulting effect; allow effect presets and portable versioned graph definitions. Consider a script editor when an appropriate DSP language and license are qualified.

Reuse HyperShader's proven frontend ideas (current native Qt dock, narrowly scoped bridge, drafts/recovery, explicit export/apply and validation feedback). Do not assume shader preview execution is suitable for audio. Avoid mandatory WebEngine or frontend API dependencies in the headless DSP module.

## Effect discovery

User wants external effects easy to find. The eventual library should bring native blocks, installed third-party effects, community HyperDSP definitions and discoverable upstream collections into one searchable surface, showing format, compatibility and installed/available state. Reuse the current LADSPA catalog scanner and versioned metadata; do not load unknown native libraries merely to browse an online listing. Acquisition should be explicit and provenance visible. Prefer package-manager or official-source links before implementing any downloader. Favorites, tags and author-defined controls should work across supported backends. Unsupported formats can be discoverable as clearly labeled unavailable, never silently loaded.

The graphical library and JSON export share the [effect inventory](effect-library.md). The [effect graph](effect-graph.md) supports the native registry, gain and compatible scanned LADSPA effects, with known fixed native latency alignment and shared parameter definitions. Graph modulation targets exposed macros through four shared reactive routes. Macros can map multiple parameters and generate OBS sliders. Accepted graphs and macro values survive OBS source serialization and recreation; rejected drafts remain separate, with explicit Restore working graph. Favorites, acquisition, additional format adapters and sidechains remain future work.

## Dock behavior

The optional Qt 6 Widgets frontend registers with OBS on FINISHED_LOADING using obs_frontend_add_dock_by_id, and removes itself on EXIT/unload. DSP-only builds remain possible. It exposes a compact theme-aware graph canvas, searchable library (native/installed LADSPA and gain utility), explicit scan/reload, output selector, generated parameter inspector, weighted input editor, and import/export. Catalog entries and parameters use the existing native/LADSPA metadata (shared with the CLI). Ineligible library entries are disabled. Search operates on a cached inventory; explicit reload refreshes installed metadata. Nodes start in index-based positions and can be dragged, including the input/output terminals. The canvas maintains positions across graph edits within the current draft, updates cable geometry continuously, and routes skip connections beneath intermediate nodes where possible. Drag from an output port to an input port to append a unity-weight connection; dragging to the Output terminal reroutes the final output. Select a cable and press Delete or use its context menu to disconnect. Cycles, duplicates and connection limits are rejected, and the last input of a node is protected. Disconnected intermediate nodes may exist in drafts but are rejected by production validation. The inspector remains available for precise weights and source changes. Ctrl+wheel zooms; Fit fits the graph, Layout resets positions. Positions persist with local editor documents and presets; importing plain graph JSON or loading a target without editor metadata uses the default layout. DSP JSON is unchanged by layout. Node removal is intentionally limited to a final output leaf with one input and no exposed bindings.

The user explicitly selects an existing Graph filter by parent/filter UUID; target refresh does not silently retarget a removed selection. Draft editing, import and load do not modify live settings. The versioned internal source procedure hyperdsp_graph_apply_v1 accepts graph and validate_only, returns ok/status, and prepares using the same runtime and admission checks as normal graph edits. Validation does not publish; apply publishes the prepared candidate once, updates settings and refreshes properties. Failed preparation leaves the target's draft, live graph and recovery unchanged. Existing macro values are retained by stable ID. External validation can instantiate trusted libraries and start subscriptions temporarily; no audio is routed or sandbox implied. Graph replacement has the existing no-crossfade limitations. Import rejects duplicate JSON keys and oversized files; export uses QSaveFile. Macros are editable in Controls; reactive routes are editable in Modulation. A rejected imported draft may be exported deliberately.

Verification: the Qt Widgets event-driver regression uses the actual widget and real libobs source/filter, searches and adds Hard clipping, edits drive, validates without publishing, applies via the production graph procedure, rejects invalid output without changing settings, and adds an actual weighted parallel edge to a second node. Rendered widget screenshot inspected at 880×620; isolated OBS startup with temporary config and staged installation logged successful dock registration. The real Qt viewport test also drags a node, verifies unchanged DSP JSON, deletes and reconnects a parallel cable, rejects duplicate/cyclic cables, reroutes output and rejects the disconnected draft on Apply, restores the output and protects the sole input cable. A rendered 880×620 screenshot after moving the node was inspected. This does not prove full live desktop interaction, preview or every external effect. The user must add a Graph filter manually before selecting it. Community library integration remains future work.

## Proposed implementation order

1. Expand native DSP building blocks (dynamics, saturation, delay, modulation/time effects, reverb).
2. Establish backend-neutral parameter metadata, effect graph schema and bounded serial/parallel routing, explicit sidechain inputs and latency accounting. Validate graphs off the audio thread; prepare resources off callback, publish a safe prepared graph, keep last working graph on errors. Feedback loops need explicitly bounded delay semantics; arbitrary cycles are rejected.
3. Add reusable presets, graph import/export and deterministic offline/real OBS audio verification. Establish safe preview routing, levels and bypass; do not silently alter program audio.
4. Add optional frontend dock: nodes, connections, parameter inspector, live waveform/spectrum and response visualization, modulation mapping, draft recovery, explicit preview/apply. Reuse existing native and LADSPA adapters rather than implementing DSP in the UI.
5. Extend to additional qualified effect hosts and optional script authoring.

Sight and Sound provide optional data inputs to modulation, not DSP nodes that load models. Aftermarket remains responsible for OBS interaction/routing, not effect execution. No new mandatory neural or GUI dependency.

The graph has a versioned JSON contract and the dock uses native Qt Widgets. Portable external identities and script language remain open pending real runtime and licensing evidence.

Theme integration: all ordinary widgets inherit OBS styles, without local fixed color stylesheets. Custom graph graphics use the effective graph widget palette, including host stylesheet overrides and active/inactive/disabled roles, rather than only the top-level dock palette. Text is contrast-corrected against its actual surface (4.5:1 target), accents/cables/selected outlines against their backgrounds (3:1 target); selected nodes also use a thicker outline, and inverted cables remain dashed. Plot widgets declare their Base/Text roles so custom theme stylesheets affect their rendered backgrounds and labels. Graph labels use the graph's effective font and elide to fit the existing cards. Palette/style/font and OBS THEME_CHANGED notifications update existing items in place, coalescing Qt's propagation events, preserving selection, layout, zoom and draft. The refresh is disconnected before scene destruction. Qt regression exercises two custom light/dark palettes, graph-local palette, actual QSS override, low-contrast text, selection, font updates and rendered pixels on all five dock plot widgets; graph/draft state is retained. The complete local Linux Release CTest inventory passed 56/56 without skips after this change, including the standalone analysis and real libobs audio tests. A teardown regression exposed by the expanded widget test was traced to a selection callback during scene destruction and corrected by deferring refresh and disconnecting before teardown. Full desktop OBS Colorway switching and native platform visual checks remain unverified.

Controls tab: create up to eight named macros with generated stable IDs (renaming does not change the ID), set normalized defaults, and bind numeric parameters across nodes. Targets come from shared metadata; choices, LADSPA integer/toggle controls and already-bound targets are excluded. Endpoints are editable in parameter units and may be reversed. The existing graph compiler is the final authority; a macro without bindings cannot apply. The UI supports removing bindings and macros, but protects macros referenced by existing modulation routes. Changing defaults does not overwrite an existing OBS user value associated with the stable ID. No live edits until explicit Apply. Actual widget test authors a two-node macro, applies it, checks the real generated OBS slider, verifies duplicate/choice target exclusion, binding deletion, route-referenced macro protection and draft-only removal. Rendered Controls tab inspected. Mode-irrelevant numeric parameters remain visible, as in the shared inventory; route authoring is available in the Modulation tab.

## Modulation tab

Create a named exposed control first, then add up to four routes. Choose a source and destination by stable control ID; route labels display source → control name. Signed amount adds a normalized contribution to the manual macro value. LFO exposes waveform and rate, envelope and band detectors expose attack/release, and band detectors also expose sensitivity. Sound category confidence uses the existing classifier channel discovery plus an exact category label; Sight motion and hand routes use the existing producer discovery. Refresh inputs updates the available choices. Unavailable saved IDs remain visible and are preserved; switching between unrelated signal domains clears the old channel/category rather than silently redirecting it. Hand X/Y/pinch share the hand-channel domain. Routes may target the same macro and their contributions sum in the existing runtime. Deleting a route is draft-only; referenced controls remain protected until their routes are removed. No changes to DSP or live audio until explicit Apply. Validation is still performed by the production graph compiler. Native Qt widgets inherit OBS theme; no custom colors. The route editor uses a scrollable layout with source-dependent rows.

Verification: real Qt widget test creates an LFO route with signed depth, waveform and rate, discovers Sound and Sight fixture channels, adds a band route, enforces the four-route limit, applies the exact authored JSON through the production OBS graph transaction, preserves a missing saved Sound channel, rejects an incomplete route without changing the live filter, and removes a route from the draft. It also checks source-dependent visibility and actual control geometry at narrow width. Rendered 880×620 and 420×640 screenshots inspected. This is a route form editor, not modulation cables on the main audio canvas, nor a per-route live signal meter; the existing graph audio integration suite covers signal behavior with contract fixtures. Live inference and desktop theme switching remain unqualified.

## Live Monitor

The Monitor tab reads actual audio entering and leaving the selected, applied HyperDSP Graph filter. Channel 1 for the waveform and spectrum is intentional: opposite-phase stereo cannot disappear into a misleading downmix. Paired 1024-sample windows feed the waveform, peak dBFS readouts and a log-frequency Hann-windowed FFT magnitude plot (calibrated for a bin-centered sinusoid; -90 dBFS plot floor, not a power spectral density). At 48 kHz each window covers 21.3 ms with 46.875 Hz bin spacing. Input is dashed, output solid; both use contrast-corrected OBS palette roles. The waveform displays amplitude up to ±1; peaks above unity remain measurable in the numeric status. The macro readout shows the active graph’s named base and effective normalized values at the end of the captured host block. It is not a per-route activity meter, or a sample-exact measurement of smoothed engine parameter values. Input/output are simultaneous callback windows, not latency-aligned or a transfer-function estimate.

The dock reads the bounded, caller-owned `hyperdsp_graph_monitor_v3` snapshot; V1 and V2 procedures remain available for earlier callers. A read renews a one-second capture lease; the audio callback copies channel 1 and (for exactly two channels) channel 2 only while leased, using preallocated buffers, three preallocated, atomically pinned snapshot slots for publication and no FFT or producer calls for monitoring. The UI polls at 20 Hz only while visible, computes FFT on the UI thread only for new snapshots, and clears snapshots older than 500 ms or invalidated by graph replacement/processing bypass. The audio thread never waits for a monitor reader; it may drop a publication when both spare slots are pinned by readers. Capture is local in memory, not recorded or exported. No additional audio processing latency or change to graph JSON. See [real-time profiling](realtime-profiling.md) for measured callback/telemetry contention and simultaneous graph workloads. These are not worst-case deadline guarantees.

Actual libobs test feeds 1.5 kHz stereo with opposite phase, verifies the correct FFT bin (32 at 48 kHz), input -7.9588 dBFS and output -13.9588 dBFS from a -6 dB gain node; a square-LFO route reports base 0.5 and effective 0.75. Graph replacement invalidates the old frame, bypass is identical, stale data clears, and deterministic lease/partial-window tests pass. The real Qt widget test receives actual OBS audio, displays the live frame, and clears on inactivity. Rendered normal and narrow screenshots inspected. Physical audio devices and desktop Colorway switching are not qualified by these tests. Isolated draft response and synthetic tone analysis are available in Preview; audible audition is available in Audition.

## Isolated Preview

Preview runs the same native graph compiler and DSP engines on a separate worker using a snapshot of the current draft JSON, OBS audio format, test frequency and level. It does not read microphone audio, publish OBS settings, modify the live graph or output audible samples. It works without selecting a target filter. Draft macro defaults are used rather than live OBS overrides. The bounded 0.5-second sine is duplicated to all channels and the last 1024 samples of channel 1 are shown as paired waveforms and spectra, with window RMS and peak dBFS. Local reactive routes run from synthetic input and LFO state; external routes use zero contribution, with an explicit notice. Only built-in native nodes are admitted: LADSPA nodes are rejected before instantiation. This is instance isolation, not an OS sandbox. The same strict JSON parser is shared with live graph preparation.

Stationary graphs consisting of gain and native filter nodes with no modulation routes additionally receive a measured magnitude curve from a separate fresh engine fed a unit impulse. The 32768-sample finite response is FFT-transformed without a window and sampled at 257 log-spaced frequencies from 20 Hz to min(20 kHz, 0.49 × sample rate), interpolating magnitude between bins. A remaining impulse tail energy warning identifies possible truncation; deep/narrow notches and long ringing are only approximate. Nonlinear/time-varying and other unqualified families receive tone analysis only, not an LTI transfer curve. No phase plot, latency-aligned tone comparison or multi-tone measurement in this silent analysis panel. Preview is explicit, bounded to one running job per dock, with stale results cleared after changes to draft, signal or audio format; hidden tabs stop polling and retrieve finished results when shown. All plotting uses the OBS palette.

Core verification: flat -6 dB gain, 1 kHz low-pass response (-3.015 dB at the nearest sampled point and -42.54 dB near 10 kHz), hard clipping and reactive tone-only classification, deterministic repeat, malformed graph/invalid signal/external node rejection. Actual Qt widget regression measures the unapplied low-pass, switches to tone, invalidates after a draft edit, renders nonlinear clipping, rejects an invalid draft and confirms the live OBS filter settings never change. Rendered response and tone screenshots inspected. No physical audio device qualification in the silent analysis tests.

## Audible A/B audition

Audition is a separate draft-only transport, not an OBS source or mixer channel. Render captures graph JSON and signal settings on a worker and prepares a fresh native graph using its macro defaults. External modulation contributes zero; LADSPA nodes are refused before loading. Synthetic inputs are three-second sine, approximate pink noise (deterministic filtered noise), and logarithmic sweep (20 Hz to min(20 kHz, 0.45 × sample rate)), at the current mono/stereo OBS format. The local file picker accepts uncompressed little-endian RIFF PCM16 WAV, mono/stereo, 8–192 kHz, up to 32 MiB, rendering the first eight seconds at the file’s own rate/layout; no network URLs, microphone, compressed formats or file resampling. The renderer compensates known graph latency by padding input and cropping the wet version; effect tails beyond the comparison window are truncated.

A and B restart their respective rendered clip from the beginning. Shared attenuation preserves relative loudness, with a default listening gain of -18 dB, no amplification and a shared -12 dBFS sample-peak ceiling. Both clips receive short fades. This is a digital margin, not a guarantee of safe acoustic loudness or an intersample true-peak limiter. Audible playback is currently Linux-only. Playback is explicit, requires selecting a device discovered by pactl, and uses paplay with raw PCM via QProcess (no shell or OBS audio output calls). If these tools are missing, native analysis/render remains available, but playback cannot start. Stop and hiding the tab terminate the process; stale draft/signal changes invalidate the clip and stop playback. A running render can finish offscreen but never autoplays. Output-device routing is controlled by the OS: desktop-audio or device-monitor capture can still pick up audition sound, so select an uncaptured output; no guarantee against recording. No device default changes or live settings writes.

Verification: core deterministic sine/pink/sweep A/B gain parity, shared peak ceiling, stereo PCM16 decoding, malformed WAV/graph rejection and LADSPA refusal; Qt test renders pink noise, verifies no auto-selected device, uses the actual file picker and renders a generated 8 kHz mono WAV, invalidates a changed draft, and checks the live filter is unchanged. Optional integration test sets HYPERDSP_AUDITION_TEST_SINK to a test-only sink name and exercises real playback, tab-hide stop, and WAV playback. The local PipeWire PulseAudio-compatible server was tested with a temporary null sink and an observed sink input; the default sink was preserved and the temporary sink unloaded. The full native CI matrix covers isolated rendering and Qt interactions on Windows/macOS, not native device playback, which remains unimplemented. No listening test on physical headphones/speakers or OBS desktop capture isolation claim.

## Draft recovery and local presets

The Presets tab lists the installed bundled graph examples and named local presets. Save as preset creates a new unique-ID file, even if a name is reused; loading restores the graph and custom node positions as an editable draft. Nothing is applied automatically. New draft, import, load target, load preset and Restore previous preserve the outgoing document in one previous-draft slot before replacing it. Restore previous swaps the two drafts. Plain graph import/export remains schema 1 and intentionally excludes editor positions. Local presets are editor documents, not executable plugins; they may contain unfinished or invalid graphs, and Apply still uses the production compiler.

The local module configuration directory effect-builder contains recovery.json, previous.json and presets/<uuid>.json. Version-1 editor envelopes contain graph, positions and name. Graph JSON is limited to 64 KiB, editor envelopes to 96 KiB, with strict duplicate-key parsing and validated bounded layout coordinates and indices. Writes use QSaveFile with no direct-write fallback. The dock checks for changed graph/layout at 500 ms intervals and flushes on destruction; a successful recovery never selects a live target automatically (including after Refresh). No live control values, audio, file audition paths, device selection or target IDs are persisted. Corrupt recovery is preserved, autosave paused, and explicit New draft archives the unreadable bytes under a unique filename before enabling recovery again. Each file replacement is atomic, but the previous/current pair is not a single atomic transaction. This is a single active draft and one previous slot, not full multi-document history; no preset rename/delete UI, cloud sync, or portable layout export yet.

Verification uses a temporary isolated storage directory: storage round-trip, invalid graph recovery, distinct same-name presets, malformed/oversized layout rejection, duplicate-key corruption, and path traversal rejection; actual Qt test drags a node, saves a named preset, starts a new draft, restores previous, reloads the preset, checks on-disk recovery before closure, reconstructs the widget and checks graph/layout and unselected target after refresh. Corrupt bytes survive automatic editing and are archived by explicit New draft. Rendered Presets tab inspected. No real user configuration was changed by these tests.

See the [preset guide](presets.md) for the bundled library. Names are displayed in readable title case with tooltips showing effect count, modulation route count and exposed macro names. All bundled presets are covered by the production graph-presets integration regression.

## Live stereo and spectrum difference

Monitor offers Waveform / spectrum, Stereo vectorscope, and Spectrum difference. V2 of the in-process snapshot procedure (hyperdsp_graph_monitor_v2) includes the unchanged V1 signal record plus paired right-channel input and output samples from the same 1024-sample windows. V1 remains available with its original layout and procedure. The stereo flag is true only for a two-channel graph with both buffers present; partial windows reset on layout changes. The same demand lease and bounded snapshot publication are used, with no additional fixed audio latency. All analysis and drawing run on the UI thread; capture adds bounded sample copying while leased.

Vectorscope plots (L-R)/2 horizontally and (L+R)/2 vertically, in fixed full-scale coordinates, with larger input dots and smaller output dots in inherited contrast-corrected palette colors. The exact displayed output window provides cross-power correlation, fold-down power loss relative to mean channel power (floor -120 dB), and side energy fraction. Unlike the standalone stereo filter diagnostics, these are unweighted short-window metrics, not 250 ms exponential averages. Silent output is unavailable, and single-channel correlation is undefined. Spectrum difference is output minus input magnitude in dB for simultaneous channel-1 FFT bins, with inputs below -60 dBFS and outputs at the numerical floor masked. Values outside ±24 dB are clipped on the plot. It is not a transfer function, gain-reduction readout, or latency-compensated analysis; nonlinear, time-varying and delayed signals can alter it.

Verification: real OBS opposite-polarity 1.5 kHz audio through -6 dB gain, paired samples and v1/v2 sequence parity, correlation -1, fold -120 dB and spectral difference -6 dB. Core tests cover silence, single channel, in-phase audio, mixed-layout partial-window rejection and existing lease/epoch behavior. The Qt test selects both new views, verifies metric text and stale clearing, and captures normal/narrow layouts. No physical audio device or worst-case UI/audio-thread performance benchmark. Per-node dynamics and Dynamic EQ activity are now available; see below.

## Live node activity

The Monitor tab includes Node activity, with a selector listing supported nodes by index in the applied graph, not the editable draft. Dynamics nodes show linked held detector peak and smoothed gain reduction. Multiband compression shows three independent detector peaks and smoothed reductions, and actual crossover frequencies. The upper bar displays detector peak from -60 to 0 dBFS; the lower bar fills from the right over 0–30 dB reduction. Numeric labels retain values outside these display ranges, with detector floor -120 dBFS. These are the compressor detectors’ held peak values, not RMS or independent band output meters. Reduction is internal smoothed gain before makeup, wet/dry and trim; the limiter’s final instantaneous ceiling clamp is not included.

Dynamic EQ displays the engine’s current ramped center frequency/Q, held detector peak and signed smoothed gain. Its frozen wet response is evaluated analytically from the actual unity-center TPT bandpass summation H = 1 + (A-1)B using bilinear-warped frequency. It excludes trim and mix, assumes coefficients and dynamic gain are fixed at the snapshot, and is not a measurement of a time-varying graph transfer function.

The new hyperdsp_graph_monitor_v3 caller-owned snapshot embeds the unchanged V2 record plus a bounded array of 16 node states (unsupported nodes marked None). V1/V2 remain available. Only while the existing capture lease is active, the callback reads existing detector/gain state after processing the host block and publishes with the waveform snapshot using the same bounded snapshot exchange. No per-sample telemetry calculations, allocation, mutex acquisition or additional latency; plots are evaluated on the UI thread. Node selection is rebuilt on changes to the applied node inventory and clears on stale/invalidated data. The displayed state is end-of-block, not an average or exact sample alignment to the FFT window.

Real OBS tests verify the parallel Dynamic EQ, compressor and multiband branches at 1.5 kHz, including -8.99995 dB EQ, -16.5263 dB compressor reduction (signed), -15.7453 dB mid-band gain, low/high neutral, independent detector peaks, analytical center/low-frequency response, invalid ABI size rejection, replacement and stale clearing. Qt tests select all three node types from actual applied audio. Both transient modes now report signed contour and gain; other effects without telemetry are excluded; standalone filters expose the same plots in a separate modeless analysis window via their native properties button; see [standalone analysis](filter-analysis.md). No physical device or worst-case callback benchmark.

Transient node activity uses two bipolar meters per active band: normalized envelope contrast (decay/onset) and signed contour gain before wet/dry and trim. This is the last processed sample state, not a held peak, RMS or exact output gain. The graph selector includes both broadband and three-band nodes.
