# Effect Builder

User proposed an audio Effect Builder dock analogous to HyperShader's Shader Builder. The initial native Qt dock is implemented; the wider vision below remains the direction.

## Intended experience

A dock for composing, previewing, saving and applying reusable deterministic audio effects, not just browsing plugins or changing one filter's parameters. A compact theme-aware, dockable interface with an editable signal graph, searchable blocks, a parameter inspector and a visible modulation layer. Expose selected graph parameters as controls on the resulting effect; allow effect presets and portable versioned graph definitions. Consider a script editor when an appropriate DSP language and license are qualified.

Reuse HyperShader's proven frontend ideas (current native Qt dock, narrowly scoped bridge, drafts/recovery, explicit export/apply and validation feedback). Do not assume shader preview execution is suitable for audio. Avoid mandatory WebEngine or frontend API dependencies in the headless DSP module.

## Effect discovery

User wants external effects easy to find. The eventual library should bring native blocks, installed third-party effects, community HyperDSP definitions and discoverable upstream collections into one searchable surface, showing format, compatibility and installed/available state. Reuse the current LADSPA catalog scanner and versioned metadata; do not load unknown native libraries merely to browse an online listing. Acquisition should be explicit and provenance visible. Prefer package-manager or official-source links before implementing any downloader. Favorites, tags and author-defined controls should work across supported backends. Unsupported formats can be discoverable as clearly labeled unavailable, never silently loaded.

The shared native/installed metadata inventory and JSON export are implemented (see [effect library contract](effect-library.md)); the first graphical library is implemented; favorites and acquisition workflow are still future work. An initial executable [effect graph](effect-graph.md) supports all 38 native modes, gain and scanned compatible LADSPA, fixed branch alignment, and shared parameter definitions. Additional format adapters, sidechains and expanded editor functionality remain future work. Graph modulation now targets exposed macros through four shared reactive routes. Author-defined exposed normalized controls are implemented, including multi-target mappings and generated OBS sliders, with example graph definitions. Accepted graphs and macro values now survive OBS source serialization and recreation; rejected drafts remain separate, with explicit Restore working graph.

## Implemented first dock

The optional Qt 6 Widgets frontend registers with OBS on FINISHED_LOADING using obs_frontend_add_dock_by_id, and removes itself on EXIT/unload. DSP-only builds remain possible. It exposes a compact theme-aware graph canvas, searchable library (native/installed LADSPA and gain utility), explicit scan/reload, output selector, generated parameter inspector, weighted input editor, and import/export. Catalog entries and parameters use the existing native/LADSPA metadata (shared with the CLI). Ineligible library entries are disabled. Search operates on a cached inventory; explicit reload refreshes installed metadata. Nodes start in index-based positions and can be dragged, including the input/output terminals. The canvas maintains positions across graph edits within the current draft, updates cable geometry continuously, and routes skip connections beneath intermediate nodes where possible. Drag from an output port to an input port to append a unity-weight connection; dragging to the Output terminal reroutes the final output. Select a cable and press Delete or use its context menu to disconnect. Cycles, duplicates and connection limits are rejected, and the last input of a node is protected. Disconnected intermediate nodes may exist in drafts but are rejected by production validation. The inspector remains available for precise weights and source changes. Ctrl+wheel zooms; Fit fits the graph, Layout resets positions. Positions are session-local and reset when importing/loading another draft; DSP JSON is unchanged by layout. Node removal is intentionally limited to a final output leaf with one input and no exposed bindings.

The user explicitly selects an existing Graph filter by parent/filter UUID; target refresh does not silently retarget a removed selection. Draft editing, import and load do not modify live settings. The versioned internal source procedure hyperdsp_graph_apply_v1 accepts graph and validate_only, returns ok/status, and prepares using the same runtime and admission checks as normal graph edits. Validation does not publish; apply publishes the prepared candidate once, updates settings and refreshes properties. Failed preparation leaves the target's draft, live graph and recovery unchanged. Existing macro values are retained by stable ID. External validation can instantiate trusted libraries and start subscriptions temporarily; no audio is routed or sandbox implied. Graph replacement has the existing no-crossfade limitations. Import rejects duplicate JSON keys and oversized files; export uses QSaveFile. Macros are editable in the Controls tab; existing reactive routes are preserved but not yet editable through dedicated UI. A rejected imported draft may be exported deliberately.

Verification: Qt Test uses the actual widget and real libobs source/filter, searches and adds Hard clipping, edits drive, validates without publishing, applies via the production graph procedure, rejects invalid output without changing settings, and adds an actual weighted parallel edge to a second node. Rendered widget screenshot inspected at 880×620; isolated OBS startup with temporary config and staged installation logged successful dock registration. The real Qt viewport test also drags a node, verifies unchanged DSP JSON, deletes and reconnects a parallel cable, rejects duplicate/cyclic cables, reroutes output and rejects the disconnected draft on Apply, restores the output and protects the sole input cable. A rendered 880×620 screenshot after moving the node was inspected. This does not prove full live desktop interaction, preview or every external effect. The user must add a Graph filter manually before selecting it. No dedicated modulation editor, community library, persistent unsaved dock drafts, waveform/spectrum or safe audio preview yet.

## Proposed implementation order

1. Expand native DSP building blocks (dynamics, saturation, delay, modulation/time effects, reverb).
2. Establish backend-neutral parameter metadata, effect graph schema and bounded serial/parallel routing, explicit sidechain inputs and latency accounting. Validate graphs off the audio thread; prepare resources off callback, publish a safe prepared graph, keep last working graph on errors. Feedback loops need explicitly bounded delay semantics; arbitrary cycles are rejected.
3. Add reusable presets, graph import/export and deterministic offline/real OBS audio verification. Establish safe preview routing, levels and bypass; do not silently alter program audio.
4. Add optional frontend dock: nodes, connections, parameter inspector, live waveform/spectrum and response visualization, modulation mapping, draft recovery, explicit preview/apply. Reuse existing native and LADSPA adapters rather than implementing DSP in the UI.
5. Extend to additional qualified effect hosts and optional script authoring.

Sight and Sound provide optional data inputs to modulation, not DSP nodes that load models. Aftermarket remains responsible for OBS interaction/routing, not effect execution. No new mandatory neural or GUI dependency.

The initial graph has a versioned JSON contract; UI framework, portable external identities and script language remain open pending real runtime and licensing evidence.

Theme integration: all ordinary widgets inherit OBS styles, without local fixed color stylesheets. Custom graphics derive surfaces, outlines, labels, accents and cable colors from the active Qt palette with contrast correction. Inverted cables are dashed as well as differentiated by palette role. Palette/style changes and OBS THEME_CHANGED update existing items in place, preserving selection, layout, zoom and draft. The widget regression switches between contrasting light and dark custom palettes; full desktop Colorway switching has not been tested.

Controls tab: create up to eight named macros with generated stable IDs (renaming does not change the ID), set normalized defaults, and bind numeric parameters across nodes. Targets come from shared metadata; choices, LADSPA integer/toggle controls and already-bound targets are excluded. Endpoints are editable in parameter units and may be reversed. The existing graph compiler is the final authority; a macro without bindings cannot apply. The UI supports removing bindings and macros, but protects macros referenced by existing modulation routes. Changing defaults does not overwrite an existing OBS user value associated with the stable ID. No live edits until explicit Apply. Actual widget test authors a two-node macro, applies it, checks the real generated OBS slider, verifies duplicate/choice target exclusion, binding deletion, route-referenced macro protection and draft-only removal. Rendered Controls tab inspected. Mode-irrelevant numeric parameters remain visible, as in the shared inventory; dedicated route authoring remains outstanding.
