# Unified effect library (schema 1)

The shared registry in src/effect-library.hpp is the source of native mode labels and saved numeric values for twelve native OBS filter families. All 43 non-bypass choices are listed; bypass remains an internal selector option and the historical microphone mode 7 is not offered. The mode registry remains metadata-only; the graph runtime consumes all native modes with shared parameter definitions. Native IDs are native:<family ID>:<numeric mode>. Microphone graph IDs retain mic_modeler_filter as the stable family ID, while the standalone OBS source is hyperdsp_mic_filter. Native application requires the registered source ID and mode_key/mode; no scene settings are changed by browsing. Existing mode numbers and labels are unchanged.

Installed LADSPA descriptors come from the existing scanner JSON (schema 1), deduplicated by absolute local path plus exact descriptor label. IDs are ladspa:<path><tab><label>, local installation identities, not portable plugin or preset IDs. No library is loaded during inventory export; the explicit scanner probes native libraries in separate processes. LADSPA eligibility reflects descriptor metadata, file existence and requested layout (mono duplicated per channel; stereo requires stereo OBS). Native eligibility means a supported channel count; neither is a sample-rate check, a guarantee of safe code or proof of successful instantiation. Stale paths remain visible as incompatible. Missing/invalid catalog leaves native entries available. Categories and descriptions are metadata, not precise DSP classification.

The installed tools/hyperdsp-effects CLI accepts --catalog FILE, --search WORDS, --format native|ladspa, --channels 1..8 (default 2), --rate 8000..192000 (default 48000), --json, --help. Default path follows the [platform-specific scanner configuration directory](external-effects.md) or HYPERDSP_CATALOG. JSON top-level fields: schema (1), channels (requested layout count), sample_rate, effects (array). Common fields: id, name, category, description, format, source, maker, compatible. Native adds mode_key and mode; LADSPA adds path, label and channels. Each entry now includes graph_supported. All native and LADSPA entries include parameters (key, name, type, numeric min/max/step/default/unit, or choice default and choices with numeric value). External parameters include shared mix and trim controls plus scanned input-port hints resolved at the requested sample rate. controls_complete distinguishes old or incomplete catalogs from fully captured hint metadata; rescan to refresh. latency_known is false for LADSPA. Graph-supported does not imply compatible or qualified, and actual graph preparation validates live descriptor hints. The top-level graph_utilities array includes the gain/weighted-sum utility. Parameters are family-wide except mode-specific short-delay center bounds/defaults; visibility and routing metadata are not exported yet. See [graph contract](effect-graph.md). Search is case-insensitive ASCII token matching and uses the same word matcher as the OBS LADSPA browser. The CLI does not launch OBS, probe plugins, download, install or apply effects. Future consumers must validate settings and compatibility again before execution.

Tests load the actual OBS module and compare all twelve native mode property lists with the registry, then use a real SDK amp.so scanner fixture to verify unified search and mono/stereo eligibility. CLI tests check JSON schema, uniqueness, native mode mapping, stale/missing catalog, duplicate descriptors and invalid arguments. The optional Qt Effect Builder consumes the same metadata functions as the CLI; actual widget tests verify discovery and parameter editing.

Numeric parameter metadata includes bindable, indicating whether the graph supports macro mappings. LADSPA integer controls have bindable=false; discrete choices are not bindable. The Controls tab consumes this metadata without a second parameter registry. Native numeric parameters can remain mode-irrelevant or be interpreted discretely by the engine.

Multiband exports 17 numeric parameters; the two crossover frequencies are editable base parameters but marked bindable=false, since crossover changes reset filter state. All remaining parameters are eligible for graph macros.

Stereo imaging requires exactly two channels; the inventory marks the effect incompatible for other layouts and the graph compiler enforces that constraint. All seven stereo numeric controls are bindable.

Broadband transient shaper uses the shared seven-parameter schema. Three-band transient mode exposes 13 numeric parameters: eleven bindable controls and two base-only crossover frequencies. Mode 1 and its existing settings are unchanged.

Dynamic EQ has eleven bindable numeric parameters, including signed dynamic gain limit, center frequency and Q. The center is clamped to 45% of the active sample rate by the DSP engine.
