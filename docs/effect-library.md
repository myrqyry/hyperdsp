# Unified effect library (schema 1)

The shared registry in src/effect-library.hpp is the source of native mode labels and saved numeric values for eight native OBS filter families. All 38 non-bypass choices are listed; bypass remains an internal selector option and the historical microphone mode 7 is not offered. The mode registry remains metadata-only; the graph runtime consumes all native modes with shared parameter definitions. Native IDs are native:<OBS source ID>:<numeric mode>. Native application requires the registered source ID and mode_key/mode; no scene settings are changed by browsing. Existing mode numbers and labels are unchanged.

Installed LADSPA descriptors come from the existing scanner JSON (schema 1), deduplicated by absolute local path plus exact descriptor label. IDs are ladspa:<path><tab><label>, local installation identities, not portable plugin or preset IDs. No library is loaded during discovery/export. LADSPA eligibility reflects descriptor metadata, file existence and requested layout (mono duplicated per channel; stereo requires stereo OBS). Native eligibility means a supported channel count; neither is a sample-rate check, a guarantee of safe code or proof of successful instantiation. Stale paths remain visible as incompatible. Missing/invalid catalog leaves native entries available. Categories and descriptions are metadata, not precise DSP classification.

The installed tools/hyperdsp-effects CLI accepts --catalog FILE, --search WORDS, --format native|ladspa, --channels 1..8 (default 2), --json, --help. Default path follows the existing CLI scanner's XDG/HOME convention or HYPERDSP_CATALOG. JSON top-level fields: schema (1), channels (requested layout count), effects (array). Common fields: id, name, category, description, format, source, maker, compatible. Native adds mode_key and mode; LADSPA adds path, label and channels. Each entry now includes graph_supported. All native entries include parameters (key, name, type, numeric min/max/step/default/unit, or choice default and choices with numeric value). The top-level graph_utilities array includes the gain/weighted-sum utility. Parameters are family-wide except mode-specific short-delay center bounds/defaults; visibility and routing metadata are not exported yet. See [graph contract](effect-graph.md). Search is case-insensitive ASCII token matching and uses the same word matcher as the OBS LADSPA browser. The CLI does not launch OBS, probe plugins, download, install or apply effects. Future consumers must validate settings and compatibility again before execution.

Tests load the actual OBS module and compare all eight native mode property lists with the registry, then use a real SDK amp.so scanner fixture to verify unified search and mono/stereo eligibility. CLI tests check JSON schema, uniqueness, native mode mapping, stale/missing catalog, duplicate descriptors and invalid arguments. Not a rendered dock or graph qualification.
