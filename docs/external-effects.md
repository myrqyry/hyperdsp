# External effect discovery

The LADSPA filter properties now expose explicit Scan installed effects and Reload catalog actions. The scan uses a fixed argument vector (no shell), with posix_spawnp and a dedicated process group on POSIX or a Windows process and kill-on-close job. There is one module-wide active job; repeated clicks while it is running do not launch another scan. The child is reaped when status is read or at unload; unload terminates the active process group or Windows job. The UI is not blocked by scanning. Reload re-reads the atomically replaced catalog and updates categories/results without selecting a plugin or changing audio parameters. The current selection remains visible when filtered out. A previous catalog remains available if a scan fails before atomic replacement. Progress is status-on-reload rather than automatic live progress.

The Python scanner honors explicit CLI paths first, then platform-separated LADSPA_PATH (colon on POSIX, semicolon on Windows) if set, otherwise the following platform defaults. Paths are deduplicated after resolving symlinks. It probes trusted native libraries in child processes with bounded per-library timeout.

| Platform | Default discovery roots | Library suffixes |
| --- | --- | --- |
| Linux | ~/.ladspa, ~/.local/lib/ladspa, /usr/lib/ladspa, /usr/local/lib/ladspa, /usr/lib64/ladspa and sysconfig multiarch paths | .so |
| Windows | LOCALAPPDATA/LADSPA and ProgramFiles/LADSPA | .dll |
| macOS | ~/Library/Audio/Plug-Ins/LADSPA, /Library/Audio/Plug-Ins/LADSPA, /opt/homebrew/lib/ladspa, /usr/local/lib/ladspa | .so, .dylib |

The default CLI catalog is plugin_config/hyperdsp/ladspa-catalog.json inside the OBS config root: XDG_CONFIG_HOME/obs-studio (fallback ~/.config/obs-studio) on Linux, APPDATA/obs-studio on Windows and ~/Library/Application Support/obs-studio on macOS. macOS package tools reside in Resources/tools; other layouts use plugin-root/tools.

Probe isolation is not a sandbox; no automatic scanning, downloads, package installation or network requests. Ineligible effects are excluded. Search matches whitespace-delimited tokens in name, label, maker, category, filename, layout and format, independent of order. Category is inferred from names and is not authoritative taxonomy. Package suggestions and official collection URLs are based on local Mint apt package metadata; no claim of universal compatibility.

Verification: Python test uses a real SDK amp.so through two symlinked LADSPA_PATH directories, confirms deduplication and explicit argument override. Actual libobs property test starts from an empty catalog and invokes production scan/reload buttons, confirms real scanner output, word-order and layout filtering, no-result search, category/filename matching, package source property and LSP URL metadata. The old LADSPA audio test still exercises selection, settings reset and actual processing. The full [native CI matrix](ci.md) now verifies scanner lifecycle, discovery, installed tools and actual amplifier processing on all supported platforms; [Linux callback profiling](realtime-profiling.md) covers the SDK amplifier, not arbitrary third-party libraries. Desktop link interaction and exhaustive third-party qualification remain open. No package or plugin is installed by the test.

The scanner now records input-control port indices, names and raw LADSPA range hints alongside each descriptor. The CLI resolves them at the requested sample rate using the same hint logic as the standalone/graph host, without loading the library. Older catalogs remain readable; rescan to get full metadata. Graph nodes require a locally scanned ID and validate actual descriptors on preparation; no sandbox or universal LADSPA latency reporting.

The standalone LADSPA adapter prepares port defaults, validated values, route destinations and external subscriptions on the control path. Same-library/label/format edits publish a settings packet for the existing plugin instance; only the audio consumer writes its connected port values, modulation state and history after publication. A changed effect is instantiated and activated with initial controls before publication; superseded instances are retired via the bounded ownership handoff and destroyed off the audio callback. Invalid effects still publish dry bypass. Property construction uses accepted immutable descriptor metadata and saved route names, not mutable plugin state. Replacement is not crossfaded and may reset plugin history; third-party HARD_RT_CAPABLE declarations are not a guarantee of actual runtime safety.
