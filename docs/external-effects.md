# External effect discovery

The LADSPA filter properties now expose explicit Scan installed effects and Reload catalog actions. The scan uses posix_spawnp with a fixed argument vector (no shell), a dedicated process group and one module-wide active job; repeated clicks while it is running do not launch another scan. The child is reaped when status is read or at unload; unload terminates an active scan process group. The UI is not blocked by scanning. Reload re-reads the atomically replaced catalog and updates categories/results without selecting a plugin or changing audio parameters. The current selection remains visible when filtered out. A previous catalog remains available if a scan fails before atomic replacement. Progress is status-on-reload rather than automatic live progress.

The Python scanner honors explicit CLI paths first, then colon-separated LADSPA_PATH (if set), otherwise ~/.ladspa, ~/.local/lib/ladspa, /usr/lib/ladspa, /usr/local/lib/ladspa, /usr/lib64/ladspa and sysconfig multiarch paths. Paths are deduplicated after resolving symlinks. It probes trusted .so libraries in child processes with bounded per-library timeout. Probe isolation is not a sandbox; no automatic scanning, downloads, package installation or network requests. Ineligible effects are excluded. Search matches whitespace-delimited tokens in name, label, maker, category, filename, layout and format, independent of order. Category is inferred from names and is not authoritative taxonomy. Package suggestions and official collection URLs are based on local Mint apt package metadata; no claim of universal compatibility.

Verification: Python test uses a real SDK amp.so through two symlinked LADSPA_PATH directories, confirms deduplication and explicit argument override. Actual libobs property test starts from an empty catalog and invokes production scan/reload buttons, confirms real scanner output, word-order and layout filtering, no-result search, category/filename matching, package source property and LSP URL metadata. The old LADSPA audio test still exercises selection, settings reset and actual processing. GUI rendering, clicking upstream links, other OSes, and real-time audio CPU qualification are not tested. No package or plugin is installed by the test.
