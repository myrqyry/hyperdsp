# Transient shaping

The standalone hyperdsp_transient_filter and graph native:hyperdsp_transient_filter:1 share the Transient engine. A max-channel peak detector has instantaneous rise and 10 ms exponential release. A slower envelope follows it with adjustable rise (attack contour 5–100 ms, default 25) and fall (sustain contour 50–500 ms, default 150). The normalized difference is (fast − slow) / max(fast, slow, 0.001). Positive contrast weights attack gain; negative contrast weights sustain gain. Both signed gains range from −12 to +12 dB, default zero. The floor reduces full-strength gain at very low envelope levels; this is not a noise gate. Gain is applied equally across channels. Sustain here shapes the decaying envelope, not an independently extracted stationary sustain component; constant inputs converge to neutral, and periodic signals can have some residual gain ripple.

Supports 1–8 channels and 8–192 kHz. Amount and mix/trim changes use 10 ms ramps; time-coefficient edits update the envelope coefficients without clearing state. Bypass changes reset the detector. No lookahead, fixed buffering latency, per-channel detector, peak limiting or dedicated standalone modulation routes. Graph macros can modulate all seven parameters. Boost can exceed full scale, so leave headroom or place a limiter downstream. Frequency-selective shaping is available as a second mode; see below.

## Three-band transient shaping

Select Three-band transient shaper in HyperDSP Transient (mode 2), or add native:hyperdsp_transient_filter:2 to a graph. The original broadband mode 1 retains its settings and processing path. The standalone properties show only the relevant mode controls; switching mode resets DSP history, not saved per-mode gain values. Low/mid/high attack and sustain each have independent signed ±12 dB gain, with shared contour times, trim and mix. Defaults are neutral. Low crossover 60–500 Hz (250 default), high crossover 1000–8000 Hz (2500 default), clamped to 45% of sample rate. Crossovers are base-only; edits reset state, so they are not modulated in a graph. All eleven other numeric parameters can be bound to macros.

ThreeBandBank in three_band.hpp factors the existing phase-matched crossover, preallocated chunk processing and internal blend out of the multiband compressor. The transient shaper runs three independent instances of the existing linked envelope engine, preserving proportional channels. The recombined unmodified bands are the wet/dry reference. Unity magnitude is not phase identity; internal mix=0 retains crossover phase, true bypass removes it. No lookahead, fixed buffering latency, or peak limiting. No allocations in the processing bank.

Verification: neutral recombination within 0.15 dB across five sample rates (8–192 kHz), equality of neutral and shaped mix=0, non-default crossover, exact bypass, ramped partition and linked stereo agreement. At 48 kHz, +12 dB attack/−12 dB sustain applied to one band changes onset/decay RMS relative to neutral as follows: 80 Hz 2.86371/0.378766, 1 kHz 2.68030/0.389057, 6 kHz 2.67397/0.387585. Low-band shaping leaves the 6 kHz onset ratio at 1.00021. Actual OBS downstream capture reproduces the low/high measurements, validates mode-dependent properties and restores multiband gain settings after switching modes, compares standalone and graph results, and verifies the generated bass attack macro returns onset RMS from 0.390148 to 0.136239. Existing broadband transient and multiband compressor regressions still pass. Synthetic qualification, not a physical listening test or callback performance benchmark.

The standalone Open live analysis window supports both modes, with live signed contour and gain meters, broadband or per-band gain controls, shared timing, and deferred crossover handles in three-band mode. Applied graph Monitor also exposes both telemetry types. See [standalone analysis](filter-analysis.md).

The standalone OBS adapter publishes fixed-size settings snapshots on the control path and adopts them at audio block boundaries. Ordinary parameter updates preserve the existing detector, filter and ramp histories, without a processing mutex or contention-induced dry fallback. Explicit bypass/mode/crossover changes retain their documented reset behavior. Telemetry is invalidated on accepted updates and is published only for the currently adopted generation; telemetry snapshot contention can skip a display update, not audio processing.
