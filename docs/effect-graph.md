# Effect graph runtime (schema 1)

The headless PreparedGraph in src/framework/dsp/effect_graph.hpp compiles a single-input, single-output directed acyclic graph of existing deterministic DSP engines. GraphRuntime is a single-threaded owner for offline tests/consumers; the OBS adapter prepares a candidate on its control path and swaps the prepared pointer under a short mutex. The adapter serializes updates, and invalid candidates leave the current graph intact for the current audio format. The old graph is destroyed outside the audio mutex.

## Contract

The JSON root has schema (integer 1), nodes (array), optional controls (array) and output (integer node index, or -1 for an empty pass-through graph). Each node has effect (ID), inputs (array of edge objects), and optional params (object of numeric key/value pairs). Each input has source (index, -1 for original audio) and weight (finite [-4,4], signed, not normalized). The input array represents a weighted sum. Nodes may be in any order; the compiler topologically sorts reachable nodes. All nodes must contribute to output. Cycles, unsupported IDs, unknown/out-of-range parameters, duplicate JSON keys, wrong field types and unknown structural fields are rejected. Limits: 64 KiB JSON, 16 nodes, 32 total edges, 8 inputs and 24 parameter keys per native node (259 for LADSPA), 8 channels, 8–192 kHz. Empty graph is unprocessed audio.

Supported effect IDs: gain (gain_db in [-24,24], default 0), and all 38 non-bypass native IDs in the effect registry. The eight families are Microphone, Filter, Dynamics, Color, Time, Space, Spectral and Formant. Numeric mode values are unchanged from existing OBS filters. Native base parameters share parameter_schema.hpp with OBS property/settings adapters and hyperdsp-effects JSON export. Values must lie in declared ranges; steps are advisory UI increments. Discrete choices (oversampling, filter alignment and stages, phaser stages, vowels) are validated exactly. Moving delay modes use mode-specific center ranges/defaults (chorus 15 ms, flanger 2 ms, vibrato 8 ms). Mode-irrelevant parameters are accepted but do not affect that mode. Sample-clocked graph route/modulation settings are not exposed yet; no inference, sidechains or arbitrary feedback. Existing separate filters retain their modulation controls.

LADSPA nodes use the exact local catalog ID (ladspa:<absolute path><tab><descriptor label>). The OBS adapter passes the scanned catalog identities to preparation; headless callers must explicitly supply the allowed IDs. An absent ID, missing library, incompatible layout, or invalid live parameter rejects the candidate without replacing the current graph. Ports use numeric port_N keys (0 or 1 for toggles, integral values for integer hints), and mix/input_db/output_db use the shared mixer. Default controls are resolved from live descriptor hints at the actual rate. Scanning is explicit and the catalog is not a security boundary: selected native libraries execute inside OBS. No automatic download or installation. Catalog identities are local, not portable.

## Exposed controls

The optional controls array adds up to eight normalized author-defined macros with at most 32 bindings total (16 per control). Each object has id (1–32 ASCII letters, digits or underscores, unique), name (1–80 bytes), default (finite number in [0,1]), and bindings (nonempty array). Each binding has node (node index), parameter (exact parameter key), low and high (finite endpoints; either direction). Every target is unique across the entire graph. Endpoints must both validate against the actual node parameter schema at preparation time; choice parameters such as oversampling, filter alignment/stages and vowel selections are excluded. LADSPA integer/toggle ports are excluded, and continuous port bounds are checked against the live descriptor at the actual sample rate. Some native numeric controls, e.g. bit depth and freeze hold, are interpreted discretely by their engines. A mapping overrides its target's base value with lerp(low, high, macro value). Hidden or mode-irrelevant parameters may not change audio.

PreparedGraph resolves initial defaults and optional overrides before engine reset, then stores bounded mappings to the existing prepared engines. set_controls validates every incoming value before applying any; unknown IDs, non-finite or out-of-range values reject the update. It accepts partial updates. The OBS adapter uses graph_control_<id> settings with defaults from the graph, and regenerates native properties after a valid graph replacement. With unchanged graph JSON and audio format it updates controls on the existing graph under its audio mutex, avoiding resource recreation and preserving DSP state and delay buffers. Native continuous settings use existing smoothing, gain ramps 10 ms, microphone parameter updates and LADSPA control ports use their existing behavior (block-boundary updates); not a glitch-free real-time guarantee. No audio-rate macro modulation or graph routes yet. OBS control changes while the draft JSON is invalid may be rejected; last accepted graph remains active in-session. Stable control IDs preserve OBS values across graph replacement, including if a previously removed ID is reused; authors should not reuse an ID for unrelated semantics. Fresh graph definitions use their own defaults when no user value exists.

Two checked-in graph examples, parallel-color and vowel-space, are installed under data/graphs and tested through actual OBS properties and audio. These are reusable JSON definitions, not a preset browser or portable external-package resolver.

## Latency and lifetime

A node's input latency is the maximum cumulative fixed processing latency of its predecessors. Each faster input edge receives a prepared integer sample delay using the shared fractional-delay storage. The node then adds its own declared algorithmic latency: Color 0 or 24 samples depending on mode/oversampling, Spectral 1024 samples, gain 0. This aligns known fixed native latency, not creative delay, filter phase/group delay or OBS-wide timestamps. LADSPA has no universal latency reporting contract; any graph containing LADSPA reports additional latency as unknown and does not compensate it. Graph processing does not guarantee block partition invariance for arbitrary external plugins. Buffers are prepared once, scratch chunk size 256, processing handles arbitrary host block size by chunking; no allocation or host calls in the core processing loop. The OBS wrapper uses existing try-lock dry fallback on contention; valid replacement starts new state, with no crossfade and no CPU-budget or glitch-free guarantee. No global delay reporting or compensation. Invalid edits preserve the last accepted graph in memory only: a saved invalid JSON document may bypass on a fresh OBS session. A mismatched audio format bypasses until reconfigured. The properties expose a JSON editor and status in its description on reopening; not the finished dock, preview, draft recovery or graph parameter editor.

## Verification

Core test measures two serial processors and parallel cancellation (max error 8.9407e-8); non-topologically ordered Color (24 samples) + Spectral (1024) branch is aligned with direct input at sample 1048. Also covers rejection of invalid topology, weights, unsupported effect IDs, unknown/NaN parameters, invalid oversampling and oversized graphs; verifies partition invariance for 777-sample blocks vs per-sample processing, stereo preservation and rollback. Actual libobs test loads production HyperDSP Graph: two -6 dB gain nodes yield RMS 0.0710469 from 0.282843 dry; parallel direct-minus-transparent spectral yields RMS about 2.9e-8; invalid cycle and parameter edits retain the cancellation, as do malformed node and duplicate JSON keys; empty graph restores dry. Shared library test compares actual registered OBS float property bounds, steps, defaults and labels to the schema; CLI test checks supported flags and metadata. No installed GUI, actual user scenes, live CPU profiling, safe preview or listening test yet.

Expanded verification: all 28 additional native modes process finite nonzero audio with exact partition agreement in the test (777-sample blocks versus individual samples). Neutral EQ defaults are identity; ping-pong and reverb intentionally produce cross-channel energy. Other modes preserve a silent channel. Actual OBS mixed chain (Butterworth low-pass, linked limiter, echo) yields RMS approximately 0.0707104 / 0.0282842 for stereo input amplitude 0.4 / 0.16, consistent with the linked -20 dB sample-peak ceiling. Float parameter parity verified across all eight families. CLI lists 38 graph-supported entries with schema metadata. Graph resource usage is bounded by node count and per-engine storage but live CPU/memory budgets remain unprofiled; a maximum-length delay graph at high sample rate/channel count can be memory-intensive.

LADSPA verification: real SDK amp.so mono/stereo descriptors, combined native gain and spectral branches, cancellation max error 1.19209e-7, unknown/unscanned ID, invalid port/value and incompatible layout rejection. Actual libobs graph capture of amplifier at 0.5 followed by -6 dB gain yields stereo RMS 0.0708786 / 0.0283514; unscanned ID and invalid port edits retain 0.0708786 RMS. Standalone LADSPA and graph share LadspaEngine; external signal subscription stays in standalone OBS adapter. Graph modulation is not yet exposed.

Exposed-control verification: gain + hard clip macro produces sample 0.796214 at full intensity from 0.2 input; changing a delay graph output-gain macro after an impulse enters preserves that impulse at sample 4800 with amplitude 0.501187. Invalid ranges, IDs, duplicate targets, choices, out-of-range values and wrong node indices are rejected. Real SDK LADSPA port + native gain macro reaches unity and rejects a negative port endpoint. Actual OBS two-gain slider produces RMS 0.0710469 at default, 0.282843 at maximum, 0.0178462 at minimum and retains the minimum for invalid value 2. Both example definitions are loaded through real OBS and expose controls/process finite audio. Rendered GUI interaction, audio-rate automation, and live CPU/glitch qualification remain outstanding.
