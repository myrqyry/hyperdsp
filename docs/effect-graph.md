# Effect graph runtime (schema 1)

The headless PreparedGraph in src/framework/dsp/effect_graph.hpp compiles a single-input, single-output directed acyclic graph of existing deterministic DSP engines. GraphRuntime is a single-threaded owner for offline tests/consumers; the OBS adapter prepares a candidate on its control path and publishes it through a bounded ownership handoff. Control-side updates are serialized; audio adopts the latest prepared graph at the packet boundary without taking that mutex. Invalid candidates retain the accepted graph for the current format. Retired engines are reclaimed off the callback.

## Contract

The JSON root has schema (integer 1), nodes (array), optional controls and routes (arrays) and output (integer node index, or -1 for an empty pass-through graph). Each node has effect (ID), inputs (array of edge objects), and optional params (object of numeric key/value pairs). Each input has source (index, -1 for original audio) and weight (finite [-4,4], signed, not normalized). The input array represents a weighted sum. Nodes may be in any order; the compiler topologically sorts reachable nodes. All nodes must contribute to output. Cycles, unsupported IDs, unknown/out-of-range parameters, duplicate JSON keys, wrong field types and unknown structural fields are rejected. Limits: 64 KiB JSON, 16 nodes, 32 total edges, 8 inputs and 24 parameter keys per native node (259 for LADSPA), 8 channels, 8–192 kHz. Empty graph is unprocessed audio.

Supported effect IDs: gain (gain_db in [-24,24], default 0), and all 43 non-bypass native IDs in the effect registry. The twelve families are Microphone, Filter, Dynamics, Dynamic EQ, Transient, Stereo, Multiband, Color, Time, Space, Spectral and Formant. Numeric mode values are unchanged from existing OBS filters. Native base parameters share parameter_schema.hpp with OBS property/settings adapters and hyperdsp-effects JSON export. Values must lie in declared ranges; steps are advisory UI increments. Discrete choices (oversampling, filter alignment and stages, phaser stages, vowels) are validated exactly. Moving delay modes use mode-specific center ranges/defaults (chorus 15 ms, flanger 2 ms, vibrato 8 ms). Mode-irrelevant parameters are accepted but do not affect that mode. Graph-level macro modulation is supported; no inference, sidechains or arbitrary feedback. Existing separate filters retain their modulation controls.

LADSPA nodes use the exact local catalog ID (ladspa:<absolute path><tab><descriptor label>). The OBS adapter passes the scanned catalog identities to preparation; headless callers must explicitly supply the allowed IDs. An absent ID, missing library, incompatible layout, or invalid live parameter rejects the candidate without replacing the current graph. Ports use numeric port_N keys (0 or 1 for toggles, integral values for integer hints), and mix/input_db/output_db use the shared mixer. Default controls are resolved from live descriptor hints at the actual rate. Scanning is explicit and the catalog is not a security boundary: selected native libraries execute inside OBS. No automatic download or installation. Catalog identities are local, not portable.

## Exposed controls

The optional controls array adds up to eight normalized author-defined macros with at most 32 bindings total (16 per control). Each object has id (1–32 ASCII letters, digits or underscores, unique), name (1–80 bytes), default (finite number in [0,1]), and bindings (nonempty array). Each binding has node (node index), parameter (exact parameter key), low and high (finite endpoints; either direction). Every target is unique across the entire graph. Endpoints must both validate against the actual node parameter schema at preparation time; choice parameters such as oversampling, filter alignment/stages and vowel selections are excluded. LADSPA integer/toggle ports are excluded, and continuous port bounds are checked against the live descriptor at the actual sample rate. Some native numeric controls, e.g. bit depth and freeze hold, are interpreted discretely by their engines. A mapping overrides its target's base value with lerp(low, high, macro value). Hidden or mode-irrelevant parameters may not change audio.

PreparedGraph resolves initial defaults and optional overrides before engine reset, then stores bounded mappings to the existing prepared engines. set_controls validates every incoming value before applying any; unknown IDs, non-finite or out-of-range values reject the update. It accepts partial updates. The OBS adapter uses graph_control_<id> settings with defaults from the graph, and regenerates native properties after a valid graph replacement. With unchanged graph JSON and audio format it publishes a validated fixed-size control snapshot; audio applies it to the existing graph at the next block boundary, preserving DSP state and delay buffers without locking or recreating engines. Native continuous settings use existing smoothing, gain ramps 10 ms, microphone parameter updates and LADSPA control ports use their existing behavior (block-boundary updates); not a glitch-free real-time guarantee. Graph routes use a fixed 64-sample control quantum, not per-sample parameter writes. OBS control changes while the draft JSON is invalid may be rejected; last accepted graph remains active and is recoverable after an OBS source save. Stable control IDs preserve OBS values across graph replacement, including if a previously removed ID is reused; authors should not reuse an ID for unrelated semantics. Fresh graph definitions use their own defaults when no user value exists.

The [bundled presets](presets.md), including Parallel Color and Vowel Space, are installed under `data/graphs/`. Load them in the Effect Builder's Presets tab or use their plain graph JSON directly. They do not resolve portable external-package identities.

## Reactive graph routes

Optional top-level routes array (at most four): each object requires control (an exposed control ID), source (integer 1–10), and amount (finite [-1,1]). Optional shape (0 sine,1 triangle,2 square,3 saw), rate (.05–20 Hz), attack (1–200 ms), release (10–2000 ms), sensitivity (-24 to +24 dB), channel and category. Defaults are shape 0, rate 1, attack 10, release 100, sensitivity 0. Source IDs: 1 LFO, 2 input envelope, 3 bass, 4 mid, 5 treble, 6 Sound category confidence, 7 Sight motion, 8 hand X, 9 hand Y, 10 pinch closeness. External routes require a channel ID; Sound also requires an exact category label. Example:

```json
"routes": [{"control":"color","source":1,"amount":0.25,"rate":0.5}]
```

The graph reads the original unprocessed input for linked audio detectors and advances the shared modulation matrix once per sample. It averages each destination's summed contribution over a persistent 64-sample quantum, adds it to the manual base value and clamps to [0,1]. Mapped parameters then update in place using their engines' existing smoothing. This has control-rate (not audio-rate) precision, introduces one quantum of control response delay, and may increase CPU usage. A fixed quantum is independent of input block boundaries for deterministic native engines. External plugins can still have block-sensitive behavior. Sight/Sound snapshots are obtained from the existing worker subscriptions, never by invoking producer procedures in the callback; unavailable/stale values fall back toward the manual base. External snapshots enter at host callback boundaries. Valid graph replacement swaps the associated subscriptions; failed preparation retains previous subscriptions and graph. Author routes in JSON or in the [Effect Builder Modulation tab](effect-builder.md#modulation-tab). No feedback or node-output detector routing.

Core regression verifies a 2 Hz LFO across two gain stages, zero partition error between 777-sample blocks and single samples, input envelope, external snapshots, and rejection of invalid route definitions. Actual libobs contract-fixture tests give Sound confidence .5 RMS .0710484 and Sight hand X .75 RMS .141756, both falling back to .0178462 on unavailable signals. This is real OBS procedure and audio integration, not a live inference or CPU qualification.

## Persistent recovery

The OBS source save callback writes a per-filter graph_last_good object with schema 1, the accepted graph JSON, and all accepted manual macro values. The editable graph_json and draft settings are not overwritten by this save. On a fresh filter creation, HyperDSP first attempts the draft and only then attempts the recovery record if the draft fails. The backup is validated through the same graph compiler, local LADSPA catalog admission and control validation, and has no authority to bypass those checks. Malformed/missing records or missing external dependencies can prevent recovery; in that case the filter remains dry and the record is retained. Successful empty graphs intentionally replace the recovery record on the next save. Old scenes without a recovery record continue to work if their draft is valid.

The Restore working graph button explicitly replaces the draft and corresponding macro settings with the current accepted graph and base values. This discards the rejected draft only on user action and ordinarily does not recreate the running graph. No global recovery file, hidden cross-filter sharing, forced autosave, or persistence of DSP history. Recovery reflects the last OBS source save, not unsaved edits at the moment of a crash. Graph recreation resets DSP state; no crossfade. The restored graph may be active while draft controls still display rejected values until the user restores or corrects the draft.

Verified using actual obs_save_source, JSON serialization/deserialization, destruction and recreation of the filter and real captured audio. A bad draft restored the previous RMS 0.141757 rather than dry 0.282843, an invalid macro restored its accepted value, valid edits superseded the backup, an intentional empty graph recovered as bypass, and a malformed recovery record remained unavailable and preserved. Actual OBS property button callback restored accepted JSON and macro values with unchanged audio. Full desktop scene-file restart and rendered UI interaction are not yet qualified.

## Latency and lifetime

A node's input latency is the maximum cumulative fixed processing latency of its predecessors. Each faster input edge receives a prepared integer sample delay using the shared fractional-delay storage. The node then adds its own declared algorithmic latency: Color 0 or 24 samples depending on mode/oversampling, Spectral 1024 samples, gain 0. This aligns known fixed native latency, not creative delay, filter phase/group delay or OBS-wide timestamps. LADSPA has no universal latency reporting contract; any graph containing LADSPA reports additional latency as unknown and does not compensate it. Graph processing does not guarantee block partition invariance for arbitrary external plugins. Buffers are prepared once, scratch chunk size 256, processing handles arbitrary host block size by chunking; no allocation or host calls in the core processing loop. The OBS wrapper publishes validated graphs and fixed-size macro snapshots through the bounded real-time handoff. Audio owns mutable graph state, adopts pending changes at packet boundaries, and does not take a processing mutex; same-graph macro edits preserve node and delay history. Properties, recovery saves and builder transactions use accepted control-side metadata without locking audio. Valid structural replacement starts new state, with no crossfade and no CPU-budget or glitch-free guarantee. No global delay reporting or compensation. Invalid edits preserve the last accepted graph in memory and OBS source saves persist an independent versioned recovery record (including accepted changes pending the next audio block). If the draft fails to prepare on creation, the record is revalidated and restored when possible; otherwise audio bypasses. A mismatched audio format bypasses until reconfigured. Native OBS properties expose a JSON editor and status. The optional [Effect Builder dock](effect-builder.md) provides visual draft editing and isolated preview.

## Verification

The checks below cover graph processing and the libobs adapter. For frontend, draft preview and audition tests, see the [Effect Builder guide](effect-builder.md).

Core test measures two serial processors and parallel cancellation (max error 8.9407e-8); non-topologically ordered Color (24 samples) + Spectral (1024) branch is aligned with direct input at sample 1048. Also covers rejection of invalid topology, weights, unsupported effect IDs, unknown/NaN parameters, invalid oversampling and oversized graphs; verifies partition invariance for 777-sample blocks vs per-sample processing, stereo preservation and rollback. Actual libobs test loads production HyperDSP Graph: two -6 dB gain nodes yield RMS 0.0710469 from 0.282843 dry; parallel direct-minus-transparent spectral yields RMS about 2.9e-8; invalid cycle and parameter edits retain the cancellation, as do malformed node and duplicate JSON keys; empty graph restores dry. Shared library test compares actual registered OBS float property bounds, steps, defaults and labels to the schema; CLI test checks supported flags and metadata. These checks do not cover installed OBS GUI behavior, actual user scenes or physical listening. Separate [callback and mixer benchmarks](realtime-profiling.md) cover selected graphs and concurrent settings changes.

Historical verification of the expansion from 10 to 38 native modes: all 28 additional modes processed finite nonzero audio with exact partition agreement in the test (777-sample blocks versus individual samples). Neutral EQ defaults are identity; ping-pong and reverb intentionally produce cross-channel energy. Other modes preserve a silent channel. The actual OBS mixed chain (Butterworth low-pass, linked limiter, echo) yielded RMS approximately 0.0707104 / 0.0282842 for stereo input amplitude 0.4 / 0.16, consistent with the linked -20 dB sample-peak ceiling. Float parameter parity was verified across the eight families at that milestone. See the [effect library contract](effect-library.md) for the current inventory and parity tests. Graph resource usage is bounded by node count and per-engine storage. Selected graph workloads have been [CPU-profiled](realtime-profiling.md), but maximum graph memory and end-to-end deadlines are not qualified; a maximum-length delay graph at high sample rate/channel count can be memory-intensive.

LADSPA verification: real SDK amp.so mono/stereo descriptors, combined native gain and spectral branches, cancellation max error 1.19209e-7, unknown/unscanned ID, invalid port/value and incompatible layout rejection. Actual libobs graph capture of amplifier at 0.5 followed by -6 dB gain yields stereo RMS 0.0708786 / 0.0283514; unscanned ID and invalid port edits retain 0.0708786 RMS. Standalone LADSPA and graph share LadspaEngine; external signal subscription stays in standalone OBS adapter. Graph modulation is supported via exposed controls.

Exposed-control verification: gain + hard clip macro produces sample 0.796214 at full intensity from 0.2 input; changing a delay graph output-gain macro after an impulse enters preserves that impulse at sample 4800 with amplitude 0.501187. Invalid ranges, IDs, duplicate targets, choices, out-of-range values and wrong node indices are rejected. Real SDK LADSPA port + native gain macro reaches unity and rejects a negative port endpoint. Actual OBS two-gain slider produces RMS 0.0710469 at default, 0.282843 at maximum, 0.0178462 at minimum and retains the minimum for invalid value 2. Both example definitions are loaded through real OBS and expose controls/process finite audio. Later Qt tests exercise rendered macro editing and Apply; [callback benchmarks](realtime-profiling.md) cover concurrent edits. Audio-rate automation and physical-device glitch qualification remain outstanding.

Multiband node native:hyperdsp_multiband_filter:1 uses phase-matched three-band compression. Crossover parameters low_hz and high_hz are base-only, not macro targets; dynamics and mix/trim parameters can be mapped. The reported fixed latency is zero, not zero phase: an external parallel dry branch is not phase-matched by the graph latency aligner. Use the node’s internal wet/dry for parallel compression.

Stereo node native:hyperdsp_stereo_filter:1 requires a two-channel graph. Width, mid/side gains, balance and mix/trim are continuous macro targets. No fixed latency. The standalone filter provides a separate output diagnostic procedure; graph Monitor now has paired stereo vectorscope and short-window stereo diagnostics; waveform/spectrum remain channel 1.

Transient node native:hyperdsp_transient_filter:1 uses linked-channel envelope contrast and supports attack_db, sustain_db, attack_ms, sustain_ms, input_db, mix and output_db as macro targets. Zero fixed sample-buffer latency; nonlinear/time-varying preview uses the test tone rather than a transfer curve.

Three-band transient node native:hyperdsp_transient_filter:2 uses the shared phase-matched three-band bank with independent low/mid/high attack and sustain gains. The 11 continuous contour and mix/trim controls are macro targets; low_hz and high_hz are base-only. Fixed latency is zero but frequency-dependent crossover phase remains, even at wet=0. Use internal wet/dry rather than a separate unaligned dry branch.

Dynamic EQ node native:hyperdsp_dynamic_eq_filter:1 provides frequency-selective linked peak dynamics. All eleven numeric parameters can be bound to macros. This is time-varying processing; Preview uses test-tone analysis instead of a static impulse response. No fixed sample-buffer latency.
