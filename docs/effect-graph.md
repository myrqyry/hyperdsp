# Effect graph runtime (schema 1)

The headless PreparedGraph in src/framework/dsp/effect_graph.hpp compiles a single-input, single-output directed acyclic graph of existing deterministic DSP engines. GraphRuntime is a single-threaded owner for offline tests/consumers; the OBS adapter prepares a candidate on its control path and swaps the prepared pointer under a short mutex. The adapter serializes updates, and invalid candidates leave the current graph intact for the current audio format. The old graph is destroyed outside the audio mutex.

## Contract

The JSON root has schema (integer 1), nodes (array) and output (integer node index, or -1 for an empty pass-through graph). Each node has effect (ID), inputs (array of edge objects), and optional params (object of numeric key/value pairs). Each input has source (index, -1 for original audio) and weight (finite [-4,4], signed, not normalized). The input array represents a weighted sum. Nodes may be in any order; the compiler topologically sorts reachable nodes. All nodes must contribute to output. Cycles, unsupported IDs, unknown/out-of-range parameters, duplicate JSON keys, wrong field types and unknown structural fields are rejected. Limits: 64 KiB JSON, 16 nodes, 32 total edges, 8 inputs and 16 parameter keys per node, 8 channels, 8–192 kHz. Empty graph is unprocessed audio.

Supported effect IDs: gain (gain_db in [-24,24], default 0); native:hyperdsp_color_filter:1 through :5; native:hyperdsp_spectral_filter:1 through :5. Numeric mode values are unchanged from existing OBS filters. Both supported native families share parameter_schema.hpp with their OBS property and settings adapters and hyperdsp-effects JSON export. Values must lie in declared ranges; steps are advisory UI increments. Oversampling choices are exactly 1, 2, 4. Mode-irrelevant parameters are accepted but do not affect that mode. Graph route/modulation settings are not exposed yet; no inference, sidechains, LADSPA execution, arbitrary feedback or external effect loading by the graph. Existing separate filters are unchanged.

## Latency and lifetime

A node's input latency is the maximum cumulative fixed processing latency of its predecessors. Each faster input edge receives a prepared integer sample delay using the shared fractional-delay storage. The node then adds its own declared algorithmic latency: Color 0 or 24 samples depending on mode/oversampling, Spectral 1024 samples, gain 0. This aligns intentional parallel paths without compensating creative delay, filter phase/group delay, or OBS-wide timestamps. Buffers are prepared once, scratch chunk size 256, processing handles arbitrary host block size by chunking; no allocation or host calls in the core processing loop. The OBS wrapper uses existing try-lock dry fallback on contention; valid replacement starts new state, with no crossfade and no CPU-budget or glitch-free guarantee. No global delay reporting or compensation. Invalid edits preserve the last accepted graph in memory only: a saved invalid JSON document may bypass on a fresh OBS session. A mismatched audio format bypasses until reconfigured. The properties expose a JSON editor and status in its description on reopening; not the finished dock, preview, draft recovery or graph parameter editor.

## Verification

Core test measures two serial processors and parallel cancellation (max error 8.9407e-8); non-topologically ordered Color (24 samples) + Spectral (1024) branch is aligned with direct input at sample 1048. Also covers rejection of invalid topology, weights, unsupported effect IDs, unknown/NaN parameters, invalid oversampling and oversized graphs; verifies partition invariance for 777-sample blocks vs per-sample processing, stereo preservation and rollback. Actual libobs test loads production HyperDSP Graph: two -6 dB gain nodes yield RMS 0.0710469 from 0.282843 dry; parallel direct-minus-transparent spectral yields RMS about 2.9e-8; invalid cycle and parameter edits retain the cancellation, as do malformed node and duplicate JSON keys; empty graph restores dry. Shared library test compares actual registered OBS float property bounds, steps, defaults and labels to the schema; CLI test checks supported flags and metadata. No installed GUI, actual user scenes, live CPU profiling, safe preview or listening test yet.
