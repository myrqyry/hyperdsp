# Clock Sync

Standalone OBS source ID: hyperdsp_clock_sync_filter. Optional CMake feature HYPERDSP_BUILD_CLOCK_SYNC (default ON) requires the libsamplerate development library. No ML or Qt dependency. It is intentionally excluded from the fixed-frame graph inventory.

## Controller and timing

Source timestamps are the default reference; alternatively estimate the first frame time from OBS monotonic callback arrival minus the current packet duration. Arrival mode is sensitive to scheduling jitter and burst delivery. Only use sources with meaningful live timing, not local file playback. Clock Sync cannot correct drift of an independent monitoring device. Positive correction means more output samples per input sample (slower input clock relative to the reference); the sign is not the hardware oscillator's frequency error sign.

An original bounded PI phase controller compares elapsed reference time against the integral of requested output sample durations. A 2-second exponential jitter filter feeds proportional gain 0.10/s and integral gain 0.0025/s² with conditional anti-windup. The applied SRC ratio is 1 plus the bounded fractional correction. The displayed drift estimate is the controller integral, not a separately calibrated physical clock measurement. Lock is a heuristic (10 seconds elapsed, absolute filtered phase error below 5 ms and correction not at its limit); convergence can take much longer. Discontinuity detection compares consecutive packet timestamps against the previous input duration; non-increasing timestamps or a difference over 70 ms reset the converter and timeline. A new segment anchors to its first reference timestamp. No continuity guarantee across discontinuities, settings changes or bypass.

libsamplerate fast/medium/best sinc converters run on preallocated application-owned interleaved buffers, returning planar output. Supported formats: 8–192 kHz, 1–8 channels, packets of 1–8192 frames. Larger/invalid packets bypass and reset. Nonfinite input samples are replaced with zero. Output timestamps follow the actual generated frame count using integer quotient/remainder; priming can produce zero output and buffer short packets. Sinc lookahead delays delivery and leaves a bounded amount of unflushed tail audio on discontinuity or teardown. No guarantee of gapless switching. Settings changes prepare a replacement converter on the control path and publish it through a bounded latest-wins ownership exchange. The audio callback adopts it at a packet boundary without taking the control mutex, allocating, or reclaiming an old converter. Returned planar buffers remain alive until OBS has consumed the packet; retired state is reclaimed by a later control publication or source destruction. A pending replacement reports acquiring. Explicit changes still re-prime the converter; no gapless transition guarantee. Application-owned buffers do not allocate in process; third-party library internals and worst-case callback performance have not been independently profiled.

The native properties refresh button reads a snapshot; the versioned hyperdsp_clock_sync_status_v1 procedure exposes available, locked, limited, drift_ppm, correction_ppm, ratio, error_ms and relocks for polling. Atomic snapshot readers do not take the processing mutex. A stale snapshot (no packet in one second) cannot report locked. This is not an automatic on-screen meter.

## Evidence and provenance

The design was motivated by [norihiro/obs-async-audio-filter](https://github.com/norihiro/obs-async-audio-filter), particularly its use of asynchronous resampling and slow feedback to correct independent clocks. HyperDSP uses its own PI controller, preallocated buffer handling, bounded correction and diagnostics; no upstream plugin source was copied. libsamplerate is linked as a system dependency (BSD-2-Clause). The upstream plugin uses a different lag-lead controller.

Core tests simulate 150 seconds each of -400, 0 and +400 ppm reference duration offset at 48 kHz stereo with 0.2 ms sinusoidal timestamp jitter. Final corrections -401.716, -0.395, +400.927 ppm; steady-state frame count difference from ideal less than 53 frames including converter lookahead, stereo proportionality and RMS preserved. Additional tests exercise all three quality modes, variable packets and 44.1 kHz mono, configured saturation at 100 ppm, invalid input and relocking. Actual libobs source-to-filter-to-downstream-filter routing processes 15,000 accelerated synthetic packets at +400 ppm, generating 7,202,828 frames (ideal 7,202,880; difference includes SRC priming), continuous timestamps and preserved stereo, with correction +401.321 ppm. The test verifies settings and diagnostics and a timestamp jump. These are simulated timestamps, not a 150-second hardware capture or measurement of monitoring stability. Physical devices, OBS arrival-mode behavior in real workloads, long-running CPU budget and listening quality remain unqualified.
