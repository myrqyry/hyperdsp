# Dynamic EQ and de-essing

The standalone hyperdsp_dynamic_eq_filter and graph native:hyperdsp_dynamic_eq_filter:1 share DynamicEq. The topology-preserving unity-center bandpass already used in NativeFilter extracts the selected frequency region from each trimmed input channel. Its max-channel absolute peak drives a linked detector (instant rise, 10 ms decay). The existing soft-knee compressor gain curve determines the dynamic magnitude, limited by the absolute value of the signed range_db. Negative range attenuates above-threshold signals; positive range boosts above-threshold signals. Ratio 1 or range 0 is neutral after gain smoothing settles. Threshold is the selected-band peak, not full-band RMS.

The wet result is input + (10^(dynamic_gain_db/20) - 1) × bandpass(input). At the center frequency, the settled gain is the requested dynamic gain. Away from center, the response approaches unity. This fixed-Q bandpass summation avoids gain-dependent pole changes and preserves neutral identity, but its off-center response differs from the existing gain-dependent parametric Peak filter. Filtering and dynamics are linked across channels without mixing their signals. Frequency and Q ramp logarithmically; threshold, ratio, knee, range and mix/trim use the existing 10 ms parameter ramps. Dynamic gain has configurable attack and release smoothing; the gain can temporarily retain its previous value during edits or release. Frequency is clamped to min(20 kHz, 45% of sample rate). Bandpass state and detector reset on bypass/format changes. Up to eight channels and 8–192 kHz.

The shared schema exposes frequency (20–20000 Hz), Q (.25–12), threshold (-80–0 dBFS), ratio (1–20), dynamic gain limit (-24 to +12 dB), knee (0–24 dB), attack (.1–200 ms), release (5–2000 ms), input gain, mix and output gain. All eleven are graph macro targets. The engine has no fixed buffering latency, lookahead, automatic speech/sibilance classification, external sidechain, detector audition, standalone modulation routes or peak limiter. Dynamic boost can exceed full scale.

Vocal De Esser is an editable two-node graph with Dynamic EQ at 6500 Hz/Q2, threshold -30 dBFS, ratio 4, range -9 dB, attack 2 ms, release 80 ms, and a downstream -2 dBFS sample-peak limiter. Its macros adjust depth 0 to -18 dB, sensitivity -18 to -42 dBFS and center 4–9 kHz. Adjust for source level and actual sibilance frequency. The limiter is not a true-peak limiter.

## Verification

The core test measures all five sample rates (8, 44.1, 48, 96, 192 kHz), with the center scaled down for 8 kHz. A loud center tone receives approximately -9 dB or +6 dB; a quiet center tone and isolated 180 Hz tone remain neutral. Wet=0 is neutral, stereo proportionality holds, and ramped updates produce identical samples across packet partitions. A simultaneous 180 Hz and 6500 Hz signal at 48 kHz measures -0.000642 dB and -8.99995 dB change respectively. After one second of silence gain recovers to approximately -0.0000435 dB. Actual libobs downstream capture reproduces -8.99995 dB attenuation, +5.99998 dB boost, quiet and off-center neutrality, bypass, matching graph application and macro return to neutral. Registry and CLI verify all eleven parameters. The Vocal De Esser preset passes the existing six-format, macro-endpoint, audition and real OBS graph integration suite. No physical listening or worst-case callback profiling yet.

The applied graph Monitor Node activity view now plots the frozen wet response using current smoothed gain and actual frequency/Q, plus detector peak. See [Effect Builder](effect-builder.md).

The standalone OBS adapter publishes fixed-size settings snapshots on the control path and adopts them at audio block boundaries. Ordinary parameter updates preserve the existing detector, filter and ramp histories, without a processing mutex or contention-induced dry fallback. Explicit bypass/mode/crossover changes retain their documented reset behavior. Telemetry is invalidated on accepted updates and is published only for the currently adopted generation; telemetry snapshot contention can skip a display update, not audio processing.
