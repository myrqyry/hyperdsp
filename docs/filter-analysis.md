# Standalone filter live analysis

Open the properties of an existing HyperDSP Dynamics, Multiband or Dynamic EQ filter and select Open live analysis. The modeless Qt dialog is tied to that exact instance; invoking the button again raises the existing window. Native OBS settings remain authoritative. Dynamics and Multiband analysis are read-only; Dynamic EQ can also edit frequency, gain limit and Q through the existing source settings. The dialog does not route audio or create another filter. It shares NodeAnalysisPlot and the actual engine telemetry extractors with graph Monitor Node activity. Its colors derive from the active Qt palette.

Dynamics shows linked held detector peak and internal smoothed gain reduction (before makeup, wet/dry, trim and the limiter's final instantaneous ceiling clamp). Multiband shows the same per band with actual crossover frequencies. Dynamic EQ shows actual current ramped frequency/Q, held detector peak, signed dynamic gain and the analytical frozen wet curve; that curve excludes mix/trim and is not a transfer measurement of a time-varying system. The bars represent detector and smoothed gain, not RMS output levels. Upper bar scale -60 to 0 dBFS, lower bar 0–30 dB reduction; text retains out-of-range values with detector floor -120 dBFS.

## Runtime contract

The optional Qt frontend exposes the property button; the native DSP module (including DSP-only builds) exposes a versioned in-process procedure hyperdsp_filter_telemetry_v1(in ptr frame, out bool available) using caller-owned FilterTelemetryFrame from node_telemetry.hpp. Version and size must match. A read renews a 1 s capture lease. Audio reads existing engine state only at the end of a processed nonempty block and only while leased, publishes via a separate try-lock, and never waits for a UI reader. No new per-sample calculations, heap allocations or fixed audio latency. Explicit settings changes, bypass, disabled reads, invalid format and processing-lock contention invalidate the snapshot. Data older than 500 ms is unavailable. The dialog polls at 20 Hz only while visible, uses a weak OBS source reference, clears stale data and closes if that source is destroyed; frontend exit/module unload destroys all remaining windows. No private OBS widget hooks or injected properties UI.

## Verification

The Qt/libobs integration creates actual standalone filters, invokes their native property button twice, verifies one dialog per instance, and feeds real synthetic 1.5 kHz stereo audio. Dynamic EQ reports -8.99995 dB, Dynamics -16.5263 dB, multiband mid -15.7453 dB with low/high neutral. Tests check live display, invalid ABI size, hidden lease expiry, bypass and enabled-state invalidation, stale expiration and source destruction. Rendered EQ and multiband windows were inspected at 360 x 300. The headless module build remains independently supported. This test uses offscreen Qt with libobs, not the user's running OBS GUI, and does not establish physical listening quality or worst-case callback performance.

## Interactive Dynamic EQ

The standalone EQ dialog displays a dashed configured gain-limit curve with a hollow draggable handle and a solid live frozen wet response when fresh telemetry is available. Drag horizontally for logarithmic center frequency and vertically for signed gain limit (-24 to +12 dB); scroll over the handle for multiplicative Q adjustment (.25–12). Numeric controls provide keyboard access. Frequency edits are bounded to 20 Hz through min(20 kHz, 45% of sample rate). The dashed curve is the configured maximum magnitude of dynamic gain, not a claim that it is currently applied. Neither curve includes mix/trim. The configured curve remains editable without live audio, including when bypassed. Graph Node activity remains read-only.

Only changed fields are submitted through obs_source_update, with drag edits coalesced at 33 ms and the final edit flushed on release; native properties are refreshed on commit, not every pointer event. Other source settings are preserved. Polling synchronizes the editor with source settings outside active edits, without interrupting in-progress numeric typing. Existing DSP ramps handle changes. No private OBS UI hooks.

The Qt/libobs regression exercises an actual mouse drag with a settings change before release, wheel adjustment, numeric changes, unchanged unrelated threshold, external settings synchronization, keyboard entry, editing with stale audio, and measured -12 dB settled DSP response after editing. Native OBS property widgets were not exercised in the running desktop session.
