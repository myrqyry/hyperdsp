# Optional Sound classification interop

Producer contract inspected in live-latent-lab-sound-public: docs/sound-signal-interop-v1.md, src/interop/sound_signal_client.hpp and src/yamnet-worker-filter.cpp.

HyperDSP resolves a selected classification filter by parent/filter UUID, validates attachment/enabled state and calls sound_signal_read_v1 with stream=category and exact category. It accepts only connected, available classification scores and clamps finite values to [0,1]. It does not instantiate inference. A single module worker polls subscriptions outside the audio callback, using weak subscription references and a packed atomic timestamp/quantized score per subscription. Bindings replaced on channel/category change have independent snapshots; audio reads only current bindings. Polling takes no DSP lock. Audio ignores snapshots more than 500 ms old, using read-start time so a delayed response cannot refresh an old sample. Shared matrix smooths new snapshot values over 10 ms. Sound itself rejects stale predictions after 2500 ms in the inspected producer.

Tests use a contract fixture registered with real libobs under the producer source ID and the actual v1 procedure signature, not an inference model. The native test verifies expected amplitude modulation, unavailable/disabled/detached producer fallback. The LADSPA test uses the actual SDK amplifier control port, checks UUID picker, slow producer expiry, missing category fallback and recovery. Both exercise actual OBS filter callbacks and stereo audio capture. A live Sound model producing category scores, frontend visual smoke, and installed-plugin migration remain unqualified. Serial polling can be delayed by a blocking producer; timestamps fail closed for audio but shutdown still depends on producer calls returning. Exact category text entry is currently used; a category inventory UI is future work.
